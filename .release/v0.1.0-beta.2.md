# Laravel Flowguard v0.1.0-beta.2

This prerelease includes the MySQL contention fix and the runnable checkout demo added since beta.1. PHP 8.3+ and Laravel 12/13 remain supported.

## Changes

- MySQL reservations probe at most two shuffled primary-key candidates from a bounded unlocked window, preventing unrelated-row lock amplification. No session isolation is changed; ordering is best effort and an empty reservation poll does not prove an empty queue.
- The repeatable Laravel demo covers tenant authorization, signed webhooks, atomic order/outbox recording, ambiguous payment outcomes, two-principal approvals, actual local HTTP timeouts, worker exits, and stale-lease fencing.
- Native MySQL/PostgreSQL drills restore all demo-host tables and resume business state against unchanged independent provider state.
- An optional Stripe **test-key-only** pilot confirms one fixed test payment, discards its application acknowledgement, persists an encrypted provider reference, then reconciles through GET-only observations. Offline contract tests and a blocked missing-secret report are not external provider acceptance.
- Publication additionally waits for the exact-commit demo-host matrix.

## Install or upgrade

```bash
composer require mykholy/laravel-flowguard:0.1.0-beta.2
php artisan migrate
php artisan flowguard:doctor
```

No core schema migration is introduced by beta.2. The additional encrypted-reference column belongs only to the generated demo host. Keep existing deduplication, lease, inbox and reconciliation history when upgrading; populated package rollback remains rejected. Existing beta.1 tags and artifacts are immutable.

The [demo setup guide](https://github.com/mykholy/laravel-flowguard/tree/main/examples/checkout-demo) is delivered in the source repository. Demo code, tests and CI tooling are excluded from the Composer distribution. The release attachments contain the runtime ZIP and SHA-256 checksum.

## Evidence and limits

Two earlier final stress suites delivered 7,200 unique local messages across 24 synchronized MySQL/PostgreSQL rounds at 100/500 workers, with zero failed workers or extra attempts and the predefined 10-second p99 limit. These are synthetic CI outcomes, not representative staging capacity. See `docs/STABLE_READINESS.md` for measurements and corrected failures.

This is a beta evaluation release. Independent human security/adopter review, real-provider acceptance, representative staging and owner-reviewed retention policies remain open in [issue #5](https://github.com/mykholy/laravel-flowguard/issues/5). No stable 1.0 claim or exactly-once external business-effect guarantee is made. The host owns credentials, tenant identity, signature verification, transport, approval identities and retention.
