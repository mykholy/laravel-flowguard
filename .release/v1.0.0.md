# Laravel Flowguard v1.0.0

This stable release commits to the documented PHP API, named parameters,
persisted schema and fail-closed behavior for the 1.x series.

## Supported scope

- Scoped, fingerprinted operation claims and owner-only completion or unknown classification.
- Durable verified-event inbox receipts and transactional outbox signals.
- Expiring fenced delivery leases, bounded attempts and host-supplied publishers.
- Read-only inspection, reduced evidence journaling and explicit host-authorized manual classification.
- Laravel 12/13 and PHP 8.3/8.4/8.5; automated SQLite, MySQL 8 and PostgreSQL 16 coverage.

```sh
composer require mykholy/laravel-flowguard:^1.0
php artisan migrate
php artisan flowguard:doctor
```

Core runtime and schema are unchanged from beta.3. Existing migrations remain
forward compatible; do not drop package tables or roll back populated state.
Review `docs/PUBLIC_API.md`, `docs/OPERATIONS.md` and `docs/RETENTION.md`.

## Evidence and integration example

The release workflow requires the exact tagged source to pass all package CI,
archive clean installations, demo-host checks and native restoration workflows.
It attaches a validated Composer ZIP and SHA-256 checksum, waits for Packagist
to index the exact commit, and verifies a fresh public Laravel installation.

The repository-only checkout demo adds Stripe's official SDK signature checking,
strict test-account/tenant/payment binding and durable event deduplication.
It remains excluded from the Composer runtime archive; the core package adds
no Stripe dependency. Sanitized real sandbox experiments and their limitations
are linked from `docs/PROVIDER_STAGING_PILOT.md`.

## Known limits and policy revision

No independent human security audit or independent adopter approval has been
completed. No representative customer staging capacity or production recovery
certification is claimed. The prior beta checklist combined those application
acceptance tasks with package versioning; v1.0.0 adopts the explicit library
release scope in `docs/RELEASE_CRITERIA.md`. Those tasks remain open and are not
being marked passed by this release.

Hosts own tenant authentication, signature verification, remote idempotency,
transport timeouts, durable two-person approvals, retention and recovery plans.
Operations stranded in `processing` after a crash remain fenced; age does not
authorize replay. There is no automatic reclamation, pruning or provider retry.
Outbox delivery is at least once. Flowguard never guarantees exactly-once
external effects, and a stable version does not authorize a live payment launch.
