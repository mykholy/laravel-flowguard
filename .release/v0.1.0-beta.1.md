# Laravel Flowguard v0.1.0-beta.1

First versioned public beta for PHP 8.3+ and Laravel 12/13.

## Included

- Scoped idempotency claims with immutable request fingerprints and owner-only transitions.
- Explicit unknown outcomes, read-only reconciliation, and authorization-gated evidence and manual classification.
- Durable inbox and transactional outbox with bounded retries and fenced leases.
- Host-supplied publisher contracts and opt-in single-message dispatch.
- Installation diagnostics, migration protection, operational guides, and reproducible database tests.

## Installation

```bash
composer require mykholy/laravel-flowguard:0.1.0-beta.1
php artisan migrate
php artisan flowguard:doctor
```

Packagist may take a few minutes to index the tag. The Composer archive and its
SHA-256 checksum are attached to this release.

## Verification

Publication waits for successful CI, all six archive-based Laravel installation
jobs, and both native MySQL/PostgreSQL restore jobs on the exact release commit.
CI covers Laravel 12/13, PHP 8.3/8.4/8.5, SQLite, and independent workers on MySQL 8
and PostgreSQL 16. A synchronized ten-worker benchmark is not a capacity promise.

## Beta limitations

This is a prerelease, not a stable production recommendation. The public API and
schema may change before 1.0; pin this version during evaluation. Do not use it to
capture live payments. Independent security review, external-provider sandbox
acceptance, representative high-concurrency staging tests, and an independent
adopter review remain open in issue #5.

The host application owns authentication, webhook signature verification,
tenant authorization, provider credentials/timeouts, downstream idempotency,
retention policy, and approval identities. Delivery is at-least-once; exactly-once
external business effects are not guaranteed. Unknown outcomes require explicit
read-only reconciliation.

## Upgrade and recovery

Review `docs/OPERATIONS.md`, `docs/RETENTION.md`, and `docs/PUBLIC_API.md` before
integration. Back up application and Flowguard tables consistently before any
upgrade. Populated migration rollback is intentionally rejected to prevent
loss of durable deduplication and reconciliation history.
