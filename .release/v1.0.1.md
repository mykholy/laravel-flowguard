# Laravel Flowguard v1.0.1

This stable release corrects deduplication in the repository-only Stripe webhook
demo. Stripe's mutable `pending_webhooks` delivery count is excluded from the
fingerprint after the SDK authenticates the full raw body. The same event with a
changed counter returns `duplicate=true`; changed event data still conflicts.

The regression reproduced HTTP 409 in v1.0.0. The corrected contract requires
HTTP 200, the original receipt identity and exactly one outbox observation.
See Stripe's [event object contract](https://docs.stripe.com/api/events/object).

```sh
composer require mykholy/laravel-flowguard:^1.0
php artisan migrate
php artisan flowguard:doctor
```

Core runtime, API, migrations and dependencies are unchanged. The SDK/demo stays
outside the Composer runtime archive. Existing v1.0.0 disposable demo hosts may
retain their version for old receipts or start a fresh disposable host; this
patch never rewrites existing receipt fingerprints. Core-package upgrades do
not require a data migration. Published tags remain immutable.

The v1 library release scope, host responsibilities and limits continue to
apply. No independent human security audit or representative production gateway
certification is claimed. This patch does not retroactively change the source
hashes or results of the earlier real sandbox experiments.
