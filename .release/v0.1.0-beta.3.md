# Laravel Flowguard v0.1.0-beta.3

This prerelease corrects the optional checkout demo's Stripe API compatibility after real sandbox execution exposed HTTP 400 on current accounts. No core API, core schema, or core runtime behavior changes from beta.2.

- Use `allowed_payment_method_types` and pin Stripe API `2026-09-30.endive` on every demo transport request.
- Add request-contract checks for the pinned version and absence of the removed parameter.
- Record real Stripe test-payment and read-only recovery evidence with sanitized independent charge-ledger checks.
- Update the README installation version.

```bash
composer require mykholy/laravel-flowguard:0.1.0-beta.3
php artisan migrate
php artisan flowguard:doctor
```

The Stripe transport lives in the repository demo and is excluded from the Composer runtime archive. Check out this tag to use the corrected demo. Existing published tags remain immutable.

Two bounded real sandbox scenarios observed one USD 5.00 test charge per intent, no live charges, and zero confirmation POSTs during resume. See `docs/evidence/stripe-sandbox-2026-10-14.md` for source hashes, the initial failure, exact fault boundaries, and what remains untested. This does not complete the external-provider pilot or independent human review gates and does not declare stable production readiness.
